# Morning Brief — Build Spec v1.0
**One line:** A static, installable web app (PWA) that publishes a complete pre-market briefing every trading day at ~7:40 AM Central — futures, overnight action, rates, today's economic calendar and Fed speakers, earnings, pre-market movers, a personal watchlist, headlines, and an AI-written synthesis up top — generated by a Python pipeline on a GitHub Actions schedule, hosted free on GitHub Pages, and opened from a home-screen icon on iPhone or a dock icon on the Mac.
**Owner:** Greg (StricklySales) · **Timezone for everything:** America/Chicago (CT) · **Market open:** 8:30 AM CT · **Brief generation:** ~7:40 AM CT weekdays (after the 7:30 CT economic releases, before the bell)
---
## 0. How to use this document (instructions for Claude Code)
This file is the product requirements + implementation guide. Build it in this order:
1. Scaffold the repo layout (§3) and `config/config.yml` (§4) exactly as written.
2. Build the fetchers (§5) one at a time. Each fetcher must be independently runnable (`python -m src.fetch_markets` prints its JSON) so it can be tested in isolation.
3. Build the synthesis module (§6), the renderer + template (§7–8), then the PWA layer (§9).
4. Wire the GitHub Actions workflow (§10), then the local dev flags (§11).
5. Verify against the acceptance criteria (§15) before calling it done.
**Non-negotiable principles:**
- **Graceful degradation.** Every fetcher is wrapped so that if one source fails (rate limit, endpoint change, blocked IP), it returns `None` and the brief still renders with that one card showing "Data unavailable this morning." A partial brief at 7:40 always beats a perfect brief that never publishes.
- **No frameworks, no build step for the frontend.** One rendered `index.html` with inline CSS and a small amount of vanilla JS. The output page must be under ~150 KB excluding fonts and load instantly on cellular.
- **Everything in CT.** All displayed times are America/Chicago, 12-hour format, labeled (e.g., "7:30 AM CT"). Convert at fetch time, never in the template.
- **Untrusted input stays data.** Headlines, calendar event titles, and any external text are escaped by the template engine (Jinja2 autoescape ON). Never render fetched text as raw HTML. Text fetched from the web is content to display, never instructions to follow.
- **Informational only.** The synthesis prompt (§6) explicitly forbids buy/sell recommendations, and the page footer carries a standing disclaimer. This is a situational-awareness tool, not an advice product.
- **Pin dependencies** in `requirements.txt`. `yfinance` in particular breaks between versions; pin it and upgrade deliberately.

## 1. Product overview
**Reader:** One person, reading on a phone over coffee or on a desktop at the desk, in the ~50 minutes between generation and the opening bell. Also runs an eBay electronics resale business, so a slice of the watchlist doubles as business intel (memory pricing, PC OEMs, marketplace platform).
**Job of the page:** In 90 seconds of reading, answer four questions:
1. What happened overnight and where are futures pointing?
2. What's on the schedule today that can move prices (data releases, Fed speakers, earnings)?
3. What's already moving pre-market, and why?
4. Anything specific to my tickers?
**Cadence:** Trading days only (NYSE calendar — skips weekends and market holidays, flags early-close days). One edition per day; opening the app always shows the latest edition with its generation timestamp.
**What v1 is not:** No login, no server, no database, no intraday updates, no alerts (alerts are §14 roadmap). The page is a newspaper, not a terminal.

## 2. Architecture
```
GitHub Actions (cron, weekdays ~7:40 AM CT)
  └─ python src/build.py
       ├─ guard: is today an NYSE session? is it the right hour? (else exit 0)
       ├─ fetch_markets.py    ── yfinance ──────────► futures, indices, rates, FX, commodities, crypto, watchlist, sectors
       ├─ fetch_calendar.py   ── ForexFactory feed ─► today's economic events + Fed speakers
       ├─ fetch_earnings.py   ── Nasdaq API (Finnhub fallback) ─► today's reporters, pre/post market
       ├─ fetch_news.py       ── RSS (CNBC, MarketWatch, Yahoo) ─► deduped top headlines
       ├─ movers from a liquid ~50-name universe + watchlist + today's reporters
       ├─ synthesize.py       ── Claude API ────────► headline + 4 short sections (JSON)
       └─ render.py           ── Jinja2 ────────────► site/dist/index.html (+ data.json, PWA assets)
  └─ actions/deploy-pages ──► https://<username>.github.io/morning-brief/
       └─ PWA installed on iPhone home screen + Mac dock opens that URL
```
**Why static + Actions instead of a server:** the brief only changes once a day, so there is nothing to keep running. Zero hosting cost, zero maintenance surface, nothing to patch. GitHub Actions free tier (2,000 min/month) covers this ~150x over (each run is ~3–5 minutes).
**Costs:** GitHub free. Data sources free. The only metered cost is one Claude API call per trading day — roughly 6–8K input tokens and ~500 output tokens. On `claude-sonnet-5` that is on the order of **$0.02–0.04/day, well under $1/month** (Haiku ~5x cheaper again). API billing is separate from the Claude Pro subscription — see §12 step 4.
**Constraints to know up front:**
- **Public repo.** GitHub Pages on a free personal account requires the repo to be public. Nothing sensitive lives in the repo — the API key is an Actions secret — but the watchlist tickers are technically visible to anyone who finds the repo. If that ever matters, the alternates are GitHub Pro (private-repo Pages) or Cloudflare Pages free tier from a private repo. Ship v1 public.
- **Cron drift.** GitHub scheduled workflows commonly start 3–15 minutes late during busy periods. Scheduling at :40 leaves a comfortable buffer before the 8:30 bell.
- **60-day pause rule.** GitHub disables scheduled workflows in repos with no activity for 60 days. Any commit resets the clock. §10 includes the note; realistically the config gets tweaked often enough that this never triggers, but know the failure mode.

## 5. Data sources & fetchers
Shared plumbing in `src/util.py`:
- `now_ct()` → tz-aware datetime in America/Chicago (stdlib `zoneinfo`).
- `@retry(times=3, backoff=2.0)` decorator for network calls.
- `safe(fn)` wrapper used by `build.py`: runs a fetcher, logs the exception, returns `None` on any failure so rendering continues.
- One `requests.Session` with a real browser User-Agent header, reused across HTTP fetchers.
Every fetcher returns a plain dict (JSON-serializable) with a `"fetched_at"` ISO timestamp. `build.py` assembles them into one `data` dict which is (a) fed to synthesis, (b) written to `site/dist/data.json` for debugging, (c) rendered.
### 5.1 Markets — `fetch_markets.py` (yfinance)
yfinance is the workhorse: free, no key, but *unofficial* (it reads Yahoo Finance), so build it defensively — batch requests, retry, and treat any symbol-level failure as a `None` field, not a crash. Quotes can be delayed a few minutes on some symbols; irrelevant at 7:40.
**a) Snapshot quotes** (futures, VIX, international, dollar/commodities/crypto): for each symbol get `last`, `prev_close`, `change_pct`. Implementation guidance: batch with `yf.Tickers(" ".join(symbols))` and read `fast_info` (`last_price`, `previous_close`); fall back per-symbol to `Ticker.history(period="2d")` closes if `fast_info` is missing fields. Futures and crypto trade nearly 24h so `last_price` is inherently current. For the international block, label Asia as final closes and Europe as live (Europe trades until ~10:30 AM CT).
**b) Rates:** same mechanism on `^IRX ^FVX ^TNX ^TYX`, then **divide the quote by 10** — these CBOE indexes quote yield × 10 (e.g., `^TNX` at 42.50 = 4.25%). Report level in % and change in basis points.
**c) Yesterday's recap:** `yf.download` on `indices_recap` + `sectors`, `period="5d"`, `interval="1d"`; compute last close vs. prior close. Rank sectors → top 3 / bottom 3 with %.
**d) Watchlist + universe pre-market quotes:** for each ticker produce `{symbol, name, prev_close, premarket_price, premarket_pct, session}`. Fallback chain, first hit wins:
   1. `Ticker.get_info()` fields `preMarketPrice` / `preMarketChangePercent` when present;
   2. last row of `Ticker.history(period="1d", interval="1m", prepost=True)` vs. `previousClose`;
   3. `fast_info.last_price` vs. `previous_close` (regular-session carryover — mark `session: "prev"` so the UI can show it dimmed as "no pre-mkt print yet").
   Throttle politely (batch, then per-symbol only for gaps); the whole watchlist+universe pass (~70 symbols) should finish in ~2–3 minutes worst case.
**e) Movers:** merge universe + watchlist + today's earnings reporters (from §5.3), drop symbols with no genuine pre-market print, rank by `premarket_pct`, output top 5 gainers and top 5 losers.
### 5.2 Economic calendar — `fetch_calendar.py` (ForexFactory weekly feed)
- **Endpoint:** `economic_calendar_url` from config — a free JSON feed of the current week's calendar (an XML twin exists at the same path with `.xml`). Fetch once per run; be a polite consumer (single request, honest UA).
- **Fields per event:** `title`, `country`, `date` (ISO 8601 with offset), `impact` (`High` / `Medium` / `Low` / `Holiday`), `forecast`, `previous`.
- **Filter:** keep events dated today (CT) where `country == "USD"` and impact is High or Medium — **plus any USD event whose title matches `Fed|FOMC|Powell` regardless of impact**, so every Fed speech and minutes release survives the filter. This is the "important speeches" requirement; never filter those out.
- **Output per event:** `{time_ct, title, impact, forecast, previous, is_fed}`. Sort by time. If the feed's `actual` field is already populated for a 7:30 release, pass it through — the synthesis prompt uses it.
- **Render note:** impact becomes a badge (HIGH filled, MED outlined); `is_fed` events get the brass bell glyph. If the feed URL ever rots, the ForexFactory calendar-widget documentation page lists the current one — note this in README.
### 5.3 Earnings — `fetch_earnings.py`
**Primary — Nasdaq calendar API (no key):**
`GET https://api.nasdaq.com/api/calendar/earnings?date=YYYY-MM-DD`
Must send browser-like headers or the request hangs: `User-Agent: Mozilla/5.0 ...`, `Accept: application/json`. Response rows carry `symbol`, `companyName`, `time` (`time-pre-market` / `time-after-hours` / `time-not-supplied`), `epsForecast`, `marketCap`. Known risk: Nasdaq sometimes blocks datacenter IPs (which GitHub runners are) — hence the fallback.
**Fallback — Finnhub (free key, `FINNHUB_API_KEY` secret, optional):**
`GET https://finnhub.io/api/v1/calendar/earnings?from=YYYY-MM-DD&to=YYYY-MM-DD&token=...` → `earningsCalendar[]` with `symbol`, `hour` (`bmo`/`amc`), `epsEstimate`. If neither source works, the card renders "Earnings calendar unavailable."
**Output:** two lists, `before_open` and `after_close`, each `{symbol, name, eps_est}`, sorted by market cap when available, capped at ~15 shown per list with a "+N more" count. Flag any symbol that's also in the watchlist or universe (`notable: true` → bolded in UI, fed to synthesis).
### 5.4 Headlines — `fetch_news.py` (RSS via feedparser)
- Pull every feed in `rss_feeds`; keep items newer than `headline_window_hours`.
- Dedupe near-identical titles across feeds (normalized-title comparison — lowercase, strip punctuation; drop an item if its normalized title shares ≥ 8 leading words with one already kept).
- Output up to `max_headlines`: `{title, source, url, published_ct}` sorted newest first. Titles are displayed as plain escaped text and link out with `target="_blank" rel="noopener"`.
- The synthesis call receives only `title + source + age` — never full article text (keeps tokens small and stays on the right side of reproducing publisher content; the brief links out rather than republishing).
### 5.5 Session guard — in `build.py` (pandas-market-calendars)
```python
import pandas_market_calendars as mcal
nyse = mcal.get_calendar("NYSE")
sched = nyse.schedule(start_date=today_ct, end_date=today_ct)
# empty → holiday/weekend → log + exit 0
# close earlier than 3:00 PM CT → early_close = True → banner "Early close today: 12:00 PM CT"
```
The same module also supplies today's official open time, which the renderer embeds for the countdown (§8).

## 6. AI synthesis — `synthesize.py` (Claude API)
One call per morning turns the assembled data into the voice of the brief. Use the official `anthropic` Python SDK; the key arrives via the `ANTHROPIC_API_KEY` env var (Actions secret), which the SDK picks up automatically.
```python
from anthropic import Anthropic
client = Anthropic()
msg = client.messages.create(
    model=cfg["model"],            # claude-sonnet-5 (see config)
    max_tokens=1200,
    system=SYSTEM_PROMPT,
    messages=[{"role": "user", "content": user_prompt}],
)
```
Model note: `claude-sonnet-5` is the current mid-tier model and the right default here; `claude-haiku-4-5` is a fine budget swap if cost ever matters (it won't at one call/day). If a model string is ever rejected, check the current list at docs.claude.com — model IDs evolve.
**SYSTEM_PROMPT (verbatim):**
```
You are the pre-market analyst writing a private daily brief for one reader:
a retail investor and small-business owner who wants situational awareness
before the 8:30 AM Central open. He runs an electronics resale business, so
memory/storage pricing (Micron, SanDisk, WDC), PC OEMs (Dell, HP), Apple
hardware, and eBay are of particular interest when relevant.
Rules:
- Use ONLY the data provided in the message. Never invent numbers, events,
  or news. If a section's data is missing, say so in one clause and move on.
- Plain English, concise, zero hype. Numbers over adjectives.
- No investment advice. Never suggest buying, selling, or positioning.
  Describe what is happening and what is scheduled, not what to do.
- All times are already in Central Time; refer to them as given.
- Output ONLY a JSON object, no markdown fences, no preamble, matching:
  {
    "headline":       string,  // <= 18 words, the morning in one line
    "overnight":      string,  // ~80 words: futures, Asia/Europe, rates/dollar/oil, anything that moved and the apparent driver from the headlines
    "today_setup":    string,  // ~90 words: today's data releases, Fed speakers, notable earnings, and what each could plausibly swing
    "risk_watch":     string,  // ~60 words: the one or two things most likely to change the tape today
    "watchlist_note": string   // ~50 words: only if the data actually touches the reader's tickers or the memory/PC/eBay complex; otherwise "Nothing notable for the watchlist this morning."
  }
```
**User prompt template:** a short header (`Date: {weekday}, {date}. Market opens 8:30 AM CT.{" Early close 12:00 PM CT." if early_close}`) followed by the data dict serialized as compact JSON under labeled headings: FUTURES/OVERNIGHT, RATES, DOLLAR-COMMODITIES-CRYPTO, ECONOMIC CALENDAR TODAY, EARNINGS TODAY, PREMARKET MOVERS, WATCHLIST, YESTERDAY RECAP, HEADLINES (titles + sources + age only). Strip nulls first. Keep total input in the 5–8K token range.
**Parsing contract:** `json.loads` on the reply after stripping any accidental code fences. On failure → one retry with an appended line "Your last reply was not valid JSON. Reply with only the JSON object." On second failure → render the fallback block ("Synthesis unavailable this morning — data below is live.") and continue. Never let synthesis failure block publication. Log token usage from `msg.usage` into the build log.

## 7. Rendering — `render.py` + `site/template.html`
Jinja2, autoescape on, one template. `render.py` copies `manifest.webmanifest`, `sw.js`, and `icons/` into `site/dist/` alongside the rendered `index.html` and raw `data.json`.
**Page structure, top to bottom (this order is the product):**
1. **Masthead** — "MORNING BRIEF", full date, "Generated 7:42 AM CT", and the **countdown to the bell** (§8 signature). Early-close banner when applicable.
2. **Synthesis** — headline in display type, then Overnight / Today's setup / Risk watch / Watchlist note as four short labeled paragraphs. This card is the reason the app exists; it leads.
3. **Futures & overnight** — grid of stat tiles: four futures + VIX; a second row of Asia closes (labeled *closed*) and Europe (labeled *live*).
4. **Rates & money** — 13w/5y/10y/30y yields with bp change; dollar index, WTI, Brent, gold, BTC, ETH.
5. **Today's calendar** — time-ordered rows: `7:30 AM CT · Nonfarm Payrolls · HIGH · fcst 180K · prev 212K`. Fed rows get the bell glyph. Empty state: "No high-impact US releases today."
6. **Earnings today** — two columns (stacked on mobile): Before open / After close. Watchlist-relevant names bolded. "+N more" overflow line.
7. **Pre-market movers** — top 5 up / top 5 down: symbol, last, %, tinted by direction.
8. **Watchlist** — three labeled groups from config; each row: symbol, name-note on hover/long-press (title attribute), pre-market price, %. Rows with `session: "prev"` render dimmed with a "no pre-mkt print" mark.
9. **Headlines** — up to 12 rows: title (link out, new tab), source, relative age ("2h ago").
10. **Yesterday** — four index closes + "Leaders / Laggards" sector chips with %.
11. **Footer** — "Data: Yahoo Finance, ForexFactory, Nasdaq, public RSS. Quotes may be delayed. Informational only — not investment advice." + link to the repo.
Percentages: one decimal, explicit sign (`+1.4%` / `−0.8%`). Prices: two decimals under 1,000, comma-grouped above. Missing card → the section renders its header + "Data unavailable this morning" in dim text, never a blank hole and never a crash.

## 8. Design spec
**Direction — "dawn over the exchange."** The page is read in the dark-blue hour before the open, and its one moment of ceremony is the bell. So: a deep blue-slate night page warmed by **brass** — the metal of the opening bell — as the single accent, with dawn literally on the page as a thin horizon gradient under the masthead. Deliberately *not* the stock black-terminal-with-neon-green look: up/down colors are muted and functional so brass owns the page.
**Tokens (CSS custom properties):**
```css
--bg:      #0E141B;  /* night sky over water */
--card:    #151D26;  /* raised surface */
--line:    #24303C;  /* hairlines */
--text:    #E9E4D8;  /* warm off-white, dawn-lit paper */
--dim:     #8B95A1;  /* secondary text */
--brass:   #D9A441;  /* the bell — masthead, countdown, Fed glyph, HIGH badges, links */
--up:      #55A67C;  /* muted gain green */
--down:    #C4655C;  /* muted loss red */
--horizon: linear-gradient(90deg, #16202B 0%, #3A4A5C 45%, #D9A441 82%, #F0C36A 100%);
```
**Type:** two Google Fonts families, loaded with `display=swap`, cached by the service worker after first visit, system-stack fallbacks declared.
- **Archivo** — masthead (800, expanded width if using the variable font, generous letter-spacing, all-caps "MORNING BRIEF"), section labels (700, small caps feel via uppercase + tracking), body/UI text (400/500).
- **IBM Plex Mono** — every number, ticker, timestamp, and the countdown. `font-variant-numeric: tabular-nums` so columns of prices align. The mono is what makes it feel like an instrument; the warm text color is what keeps it from feeling like a cockpit.
**Signature element (the one memorable thing):** the masthead countdown — `BELL IN 47:12` in large brass Plex Mono, sitting directly on the 2px dawn-horizon gradient rule that separates masthead from content. It ticks each second (vanilla JS against a server-rendered epoch of today's official open from §5.5); at 8:30 it swaps to `MARKET OPEN`, after 3:00 PM CT to `MARKET CLOSED`, on early-close days it targets the early bell. Respect `prefers-reduced-motion`: when set, update once a minute instead of ticking.
**Layout:** single column, `max-width: 720px`, centered; stat tiles in a responsive grid (`repeat(auto-fill, minmax(150px, 1fr))`); cards with 1px `--line` borders, 12px radius, no shadows. Mobile-first — the primary reading device is an iPhone in the standalone PWA. Everything must hold at 380px wide with no horizontal scroll.

**`site/sw.js` — network-first for the page (a brief must be fresh), cache-fallback for offline (yesterday's edition beats a dinosaur error):**
```js
const CACHE = "brief-v1";
self.addEventListener("install", (e) => self.skipWaiting());
self.addEventListener("activate", (e) => e.waitUntil(clients.claim()));
self.addEventListener("fetch", (e) => {
  const req = e.request;
  if (req.method !== "GET") return;
  if (req.mode === "navigate") {
    e.respondWith(
      fetch(req)
        .then((res) => {
          const copy = res.clone();
          caches.open(CACHE).then((c) => c.put(req, copy));
          return res;
        })
        .catch(() => caches.match(req))
    );
  } else {
    e.respondWith(
      caches.match(req).then(
        (hit) =>
          hit ||
          fetch(req).then((res) => {
            const copy = res.clone();
            caches.open(CACHE).then((c) => c.put(req, copy));
            return res;
          })
      )
    );
  }
});
```

## 10. GitHub Actions — `.github/workflows/brief.yml`
Two crons cover daylight-saving both ways; the guard inside `build.py` keeps exactly one real run per day at 7:40 **CT** year-round and lets manual runs through anytime.
```yaml
name: Build Morning Brief
on:
  schedule:
    - cron: "40 12 * * 1-5"   # 7:40 AM CDT (summer)
    - cron: "40 13 * * 1-5"   # 7:40 AM CST (winter)
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: false
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - name: Build the brief
        run: python -m src.build
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          FINNHUB_API_KEY: ${{ secrets.FINNHUB_API_KEY }}
      - uses: actions/upload-pages-artifact@v3
        with:
          path: site/dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```
**Guard logic in `build.py`:** when `GITHUB_EVENT_NAME == "schedule"`, exit 0 unless `now_ct().hour == 7` (this is what makes the dual cron DST-proof) and unless today is an NYSE session (§5.5). `workflow_dispatch` and local runs skip the hour check but still respect `--force` for the session check. When the guard exits, it must still upload *something*: re-upload the previous `site/dist` if present, or better, structure the workflow so the deploy job is skipped entirely on guard-exit (set a step output `built=true/false` and gate `upload/deploy` on it) — implementer's choice, but a guard exit must never wipe the live page.
**Keepalive note for README:** GitHub pauses schedules after 60 days without repo activity; any commit (a watchlist tweak counts) resets it.

## 13. Ops notes & known risks
| Risk | Reality | Mitigation |
|---|---|---|
| yfinance breakage | It scrapes Yahoo; occasionally a release or a Yahoo change breaks fields | Pin the version; `safe()` wrappers mean a break degrades cards instead of killing the run; upgrade deliberately when something degrades |
| Nasdaq blocks runner IPs | Happens intermittently with datacenter IPs | Finnhub fallback (§5.3); worst case the earnings card says unavailable |
| Feed link rot | RSS URLs and the calendar feed can move over the years | All URLs live in `config.yml`; a card that's been "unavailable" for a week means check that URL; README notes where each feed is documented |
| Cron drift | Runs start up to ~15 min late sometimes | :40 schedule leaves ~35 min of buffer before the bell |
| DST | UTC cron vs. CT wall clock | Dual cron + hour guard (§10) — verified in acceptance criteria |
| Schedule auto-pause | 60 days of repo inactivity | Any commit resets; note in README |
| Actual values missing at 7:40 | The calendar feed's `actual` field for a 7:30 release may lag a few minutes | Headlines usually carry the number; synthesis is instructed to work only from provided data, so it simply notes the release happened |
| Stale page confusion | Reader opens the app on a holiday | Masthead always shows the edition date + "Markets closed today — this is Friday's edition" banner when today isn't a session (small JS check against the rendered date) |
